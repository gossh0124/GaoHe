# GaoHe 優化與瘦身紀錄（2026-09-29 ～ 10-01）

- 狀態：已完成；瘦身前的狀態保留在 git tag `pre-slim`
- 範圍：一輪優化後，依使用者要求做一次系統瘦身

## 為什麼瘦身

優化輪把程式碼從約 2,500 行擴張到 7,300 行、測試 1.1 萬行。主要來源與核心價值關係不大：

| 移除項目 | 原因 |
|---|---|
| 同題分組＋實質跨媒體差異（`topics.py` 962 行、topic 表、CLI） | 規則式中文比對誤報最多；審查 58 個問題中約 15 個在此 |
| 每日 LLM 預算帳本（`llm_calls` 表、計量包裝） | `analyze --limit` 已能控管每次成本 |
| 依年齡分段重抓、ETag 條件請求、傳輸簽章檢查 | 改為一條規則：48 小時內的文章每 3 小時重抓 |
| 資料庫遷移框架（5 個遷移） | 尚未發佈，沒有舊資料庫需要相容 |
| 人工確認、暫停、topic 指令；Firecrawl；provider catalog | 未接上執行期或使用者未要求 |

## 瘦身後保留

監測來源 → 文章版本 → Gemini 抽說法 → Google Search（grounding）找來源 → 抓全文 → Gemini 判讀 → 保守的可見標註 → 本機頁面；加上單篇網址查核（`gaohe check`）、設定精靈與排程。

新增的唯一功能是 Gemini Google Search grounding：沒有它，移除同題比對後工具永遠無法產生可見標註。使用者預設都有 Gemini 金鑰，因此用同一把金鑰。

## 一併修正的審查問題

- 金鑰遮罩：`?key=`、`apiKey`、巢狀與分號形式、`AIza…` 字面值；header 規則不再吃掉一般段落。
- 只抓公開網址（含轉址），避免 feed 讓程式抓到本機頁面或內網。
- Gemini：讀取 RetryInfo、處理 `blockReason`／`finishReason`、連線重置重試、逾時 120 秒、評估時以引文位置取上下文。
- 推論超出證據需兩個獨立網站；評估引文至少 6 字。
- 兩個分析同時執行不會寫入重複結果；已完成的分析不會被降級為失敗。
- 金鑰／額度／限流／斷線會停止整次分析並保留文章，不消耗重試次數；`analyze` 以代碼 3 結束。
- 設定精靈拒絕所有不可列印字元（避免 `.env` 注入）；完成頁不再要求 ZIP 使用者輸入指令。
- Windows：主控台強制 UTF-8 輸出；`serve` 不與他人共用已佔用的埠。
