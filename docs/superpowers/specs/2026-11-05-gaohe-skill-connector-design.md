- 日期：2026-11-05（rev 2：納入四面向獨立審查——一致性、安全、法律與方法、可行性）
- 狀態：待使用者審閱
- 取代：`2026-09-18-gaohe-media-monitoring-v0-design.md` 的產品方向（其 §2.5「沒有單一媒體總分」、§3.2「沒有實際資料支持的媒體偏向分數」由本文件 §2 取代）。Windows 本機監測程式碼凍結於 `/legacy`。

## 0. 名詞

| 名詞 | 定義 |
|---|---|
| 寫作特徵維度 N1–N5 | 原稱「中立性維度」。對外一律使用「報導寫作特徵」，避免對個人作規範性評價（§7） |
| Cloudflare D1 | 資料庫；全文一律寫「Cloudflare D1」，不簡稱 D1 |
| 發起者 | 自行選擇文章並提交的帳號 |
| 指派複核者 | 由伺服器隨機指派任務的帳號 |
| 合格帳號 | GitHub 帳號滿 30 天、已通過影子期、未被群集偵測凍結的帳號 |
| 比對鍵（match key） | 只用於段落雜湊與引文比對的確定性正規化結果（§6.1） |
| 段落 ID | 段落比對鍵的 sha256 |
| AI 一致 | 原稱「已確認」。公開狀態，表示 ≥3 位合格指派複核者的 AI 結果達到 §9.3 共識，並標示模型名稱與版本 |

## 1. 目標

GaoHe 是開源、非官方的**已刊出新聞稿後查核與報導寫作特徵紀錄**工具，與政府澄清管道及以謠言為主的查核平台區隔。

1. 針對使用者輸入的**網址或關鍵字**進行事實查核。
2. 對**發表機構與作者**留存可追溯的寫作特徵紀錄與分項統計（用字遣詞、資訊缺漏等），由 **AI 依公開評分準則判定**，使用者不投票、不打分。
3. 可看性高，UI/UX/DX 良好。
4. 使用者能針對文章內容做深入的知識研究與事實檢核。
5. 多個使用者的 AI 產出經伺服器驗證、多帳號共識後聚合為共享紀錄，同步到所有客戶端與公開網站；每個人使用**自己的 AI 訂閱**，GaoHe 不持有任何 AI 憑證。

### 1.1 成功條件

1. 使用者在 Claude 中上傳 Skill ZIP、加入連接器網址並以 GitHub 登入，即可完成網址或關鍵字查核，無需安裝 Python 或 API key。
2. 每個公開結論都能回溯到段落 ID、證據網址、取得時間、評分準則版本、模型名稱與參與帳號數。
3. 發起者無法讓自己的文章進入「AI 一致」；同一群集（§9.4）內的帳號合計對任一機構「AI 一致」文章的參與比例不超過 20%（定義見 §9.3）。
4. 找不到證據、抓取失敗、複核衝突，都不會被轉成「有誤」或負面統計。
5. 伺服器以 Cloudflare 免費方案為目標；P0 實測不足時允許升級 Workers Paid（約 US$5／月）。資料每晚匯出至公開 GitHub repo，可遷移。
6. CI 不呼叫任何 AI 或外部服務即可驗證格式、正規化、驗證器、聚合器與攻擊情境。

## 2. 原則（取代 v0 §2.5）

1. **多維度、無總分。** 不合成單一可信度分數、不做排行榜。
2. **沒有原文片段就不成立。**
3. **找不到證據不是證明為錯。**
4. **伺服器不信任任何單一客戶端，也不信任發起者。** 公開狀態只來自機械驗證加上指派複核者的共識。
5. **政治偏頗維度 v1 暫停。** 所有新聞（含政治新聞）照常查核，但不輸出藍綠、統獨或左右分數。
6. **對事不對人。** 作者頁只呈現作品的描述統計與依據，不推論動機、不使用總評標籤。
7. **負面結論採非對稱門檻。** 「有誤」「缺少脈絡而誤導」需要更強的證據與共識，並在具名公開前經人工把關（§9.6）。
8. **不繞過存取控制，不轉傳全文。** 不繞過付費牆、登入或 CAPTCHA；伺服器不向任何人提供新聞全文。
9. **開源。** Skill、評分準則、正規化、驗證器、聚合器全部公開；已知答案題庫除外（§9.5）。

## 3. 範圍

### 3.1 包含（v1，依 §14 分階段交付）

- GaoHe Skill（Claude Agent Skill ZIP）：查核流程、評分準則 v1、JSON Schema、artifact 報告範本。
- GaoHe 遠端 MCP 連接器（Cloudflare Workers，TypeScript），自身為 OAuth 2.1 授權伺服器，GitHub 作為上游登入。
- 正規化與段落切分、驗證器、聚合器、信用、任務分派、群集偵測。
- 公開唯讀網站（Cloudflare Pages）與公開唯讀 REST API（OpenAPI）。
- 每晚開放資料匯出至公開 GitHub repo。
- 作者頁（§7.4）、申訴與人工把關流程（§9.6、§9.7）。

### 3.2 不包含（v1）

- 政治偏頗／立場維度。
- ChatGPT、Gemini 等其他 AI 客戶端（v2；格式維持客戶端中立）。
- 自動排程監測媒體新文章。
- Windows 本機監測的新功能（程式碼保留於 `/legacy`）。
- 營運方以自己的 API key 評分或抽查。
- 單一總分、排行榜、作者動機推論。
- 「直接查這個說法」產生的不綁文章主張的提交與聚合（v1 只在對話中呈現報告，§6.2）。

## 4. 架構

```text
使用者的 Claude（claude.ai / Claude Desktop，使用者自己的訂閱）
  ├─ GaoHe Skill（上傳 ZIP；需啟用程式碼執行）
  └─ GaoHe 連接器（自訂連接器網址；GaoHe OAuth → GitHub 登入）
          │ MCP（streamable HTTP，無狀態 handler）
          ▼
GaoHe 伺服器（Cloudflare Workers，TypeScript）
  ├─ OAuth 2.1 授權伺服器（@cloudflare/workers-oauth-provider 一類實作）
  ├─ MCP 工具（§4.1）
  ├─ 比對鍵正規化＋段落切分（確定性）
  ├─ 驗證器（schema 以建置期產生的驗證程式碼執行，不在執行期編譯）
  ├─ 聚合器（增量）、信用、任務分派、群集偵測
  ├─ Cloudflare D1：sources、outlet_domains、authors、articles、
  │   article_versions、paragraphs、attestations、assignments、
  │   assessments、claims、evidence、accounts、account_signals、
  │   gold_items（私有）、aggregates、appeals、moderation_log
  ├─ 暫存（Cloudflare R2，自動刪除）：驗證期間的段落全文
  └─ 公開唯讀 REST API（讀取聚合變更時重建的靜態 JSON／快取）
          ├─ Cloudflare Pages：公開網站（Astro，建置期與執行期皆讀靜態 JSON）
          └─ GitHub Actions：以專用唯讀 token 呼叫匯出端點，每晚提交到公開資料 repo
```

### 4.1 MCP 工具契約

| 工具 | 唯讀 | 用途 |
|---|---|---|
| `get_record(url)` | 是 | 取得文章的公開狀態與已公開結果（未達公開狀態者只回傳 n/required） |
| `get_scores(outlet_id \| author_id)` | 是 | 取得機構或作者的公開統計 |
| `get_review_task()` | 是 | 取得目前持有的指派（無則分派一個）：只含 URL、任務類型、結構化主張參照 |
| `submit_snapshot(url, body_text, metadata)` | 否 | 上傳抓到的正文與 metadata；伺服器切段、計算段落 ID 並回傳段落 ID 清單 |
| `submit_assessment(snapshot_ref, payload)` | 否 | 上傳主張、證據、N1–N5 標記；`kind` 為 `initial`／`review`／`supplement` |
| `report_unavailable(url, reason)` | 否 | 記錄無法取得（付費牆、登入、只有樣板內容） |
| `skip_review_task()` | 否 | 略過目前指派（§9.2 限制） |

所有回傳給客戶端的他人自由文字一律放在 `untrusted_text` 欄位；派給複核者的主張只以結構化參照傳遞（段落 ID、引文、封閉類型標籤），不傳發起者的自由文字。

### 4.2 可行性前提（P0 必須實測）

1. Skill 與自訂遠端連接器在 Pro 方案的 claude.ai 網頁版與 Claude Desktop 可用；同一次執行中 Skill 能呼叫連接器工具與內建網頁抓取。Free 方案可能只允許 1 個自訂連接器；Team／Enterprise 需 Owner 加入連接器（未確認）。
2. 以約 10 個台灣新聞網址、2 個帳號各跑 3 次，量測**比對鍵後的段落精確相符率**；相符率不足時加入近似比對（§6.1-4）或回到設計。
3. 記錄各主要新聞網域的抓取成功率（Claude 抓取工具不執行 JavaScript 並遵守 robots.txt）。
4. MCP 請求到達 Worker 時的來源 IP 是否為 Anthropic 出口（預期是），據此確認 §9.4 只使用 OAuth 瀏覽器請求的訊號。
5. 每個工具的 CPU 時間（wrangler tail）、Cloudflare D1 每日讀寫列數、KV 寫入數（OAuth token）在免費額度內的餘裕。
6. artifact 能否呼叫外部 API 或觸發新對話；預期不能，報告改為由 Skill 預先嵌入資料（§10.2）。

## 5. 分工：使用者的 AI 與伺服器

| 工作 | 執行者 | 伺服器的機械檢查 |
|---|---|---|
| 抓取文章原文 | 使用者的 AI | 伺服器自行切段、計算段落 ID；段落確認規則見 §6.1 |
| 拆解可查證主張 | 使用者的 AI | 每個主張附段落 ID＋逐字引文，伺服器自行定位 code point 位置 |
| 搜尋、閱讀證據與推論 | 使用者的 AI | 證據 URL 僅限 http/https；附取得時間、發布時間、等級、證明對象 |
| N1–N5 標記 | 使用者的 AI | 引文逐字比對、封閉標籤、數量與長度上限 |
| 獨立複核 | 伺服器指派的帳號 | 自行抓取原文，盲審 |
| 正規化、切段、驗證、聚合、信用 | 伺服器 | 確定性運算，不呼叫 AI |

伺服器不抓新聞網站，不受雲端 IP 被封鎖影響。

### 5.1 原文與著作權

- 段落全文只在驗證期間暫存於 R2，**最長 30 日後自動刪除**；Cloudflare D1 長期只保存段落 ID、段落長度與通過驗證的短引文。
- 任何 API、MCP 工具、網站或匯出都不提供段落全文；`get_review_task` 只給 URL，複核者自行抓取。
- 單則公開引文上限 60 個 code point；每篇文章公開引文總量不超過正文長度的 10%，超過的標記只顯示段落位置。
- 公開文章頁不顯示原文，只連到原始網址。
- 開放資料以 CC BY 4.0 授權，但**新聞引文不在授權範圍內**，標註「引文著作權屬原權利人，依著作權法第 52 條引用」。

## 6. 資料流程

### 6.1 快照與段落確認

1. Skill 以 Claude 內建抓取工具取得頁面，只保留**可見正文**（排除圖說、相關新聞、隱藏文字、alt、noscript）；只有樣板內容時呼叫 `report_unavailable`。
2. `submit_snapshot` 上傳正文全文與 metadata（標題、署名、發布時間）。上限：正文 ≤ 30,000 code point、段落 ≤ 200。
3. 伺服器以確定性規則切段（以換行切分，合併過短段落），對每段計算**比對鍵**：NFKC → 移除所有空白與 Unicode Cf 類字元（零寬字元、BOM、軟連字號）與變體選擇符 → 引號、破折號、刪節號的各種變體對應為單一形式。段落 ID = sha256(比對鍵)。
4. 若 P0 相符率不足，加入近似比對：字元 n-gram Jaccard ≥ 0.95 視為同一段落，保留一份標準文字。
5. **段落確認**：至少 2 份獨立 attestation，且**至少 1 份來自指派複核者**（不在發起者的群集內、非影子期）。發起者自己的多次提交只算 1 份。
6. **快照穩定**：分母為目前版本中位長度提交的段落數；已確認段落 ≥ 60% 時為「穩定」。不穩定時結果只能停在「初步」。長期無法穩定的 URL 公開標示「內容因取得方式而異」。
7. **新版本**：只有在 ≥2 份獨立 attestation（其中 ≥1 份為指派複核者）都回報一組與目前版本不同（超出比對鍵與近似容忍）的段落集合時，才建立新的 article_version。舊版結果保留並標示適用時間。
8. **metadata**：機構由伺服器依 URL 網域查 `outlet_domains` 公開對照表決定，不採用客戶端宣稱。署名、標題、發布時間須 ≥2 份獨立 attestation（含 ≥1 指派複核者）一致才確認；未確認署名的文章不計入作者統計。

### 6.2 查核與評分

1. **網址輸入**：進入 6.1。
2. **關鍵字輸入**：Skill 搜尋並列出 3–5 篇相關報導供選擇；或「直接查這個說法」——v1 只在對話中產出報告，**不可提交、不計入任何機構或作者**。
3. 拆解主張（§8）→ 搜尋證據 → 逐主張結論 → N1–N5（§7）；N5 為選用的第二階段，context 不足時略過，核心查核仍完成。
4. Skill 先呼叫 `get_record` 與 `get_scores`，把結果嵌入 artifact 報告（§10.2）。
5. 詢問使用者是否提交；連接器的工具核准提示即作為提交確認，提交前顯示摘要。
6. 驗證失敗時回傳錯誤碼與欄位（例如 `QUOTE_NOT_FOUND`、`QUOTE_AMBIGUOUS`），Skill 修正後最多重送 2 次。引文重複出現時附 `occurrence` 序號。
7. 發起者的 `initial` 提交只能引用其自己快照中已被伺服器接受的段落；在段落確認前保持「初步」，段落確認後自動重新驗證，指向始終未確認段落的標記不公開。

### 6.3 複核

1. 報告完成後，Skill 詢問是否協助一個複核任務（不在開始時打斷）。
2. `get_review_task` 只回傳 URL、任務類型與結構化主張參照。複核者**必須自行抓取原文並呼叫 `submit_snapshot`**，其段落即成為 §6.1-5 的指派 attestation；抓取失敗則 `report_unavailable`，任務重新指派。
3. **盲審**：項目達到公開狀態前，所有 API、MCP 工具、網站與匯出只顯示 n/required，不公開任何個別結論、分數或標記。
4. 禁止複核自己的提交，也不指派給發起者群集內的帳號。

### 6.4 聚合與公開狀態

- 增量聚合：每次提交只重算受影響的文章、機構與作者列。
- 狀態：
  - **初步（n/required）**：合格指派複核者不足、快照不穩定或段落未確認。不計入統計。
  - **AI 一致**：滿足 §9.3，且（若適用）通過 §9.6 人工把關。顯示模型名稱與版本。
  - **有爭議**：滿足帳號數但未達共識；並列雙方證據。
  - **申訴處理中**：§9.7，暫時排除於統計外。
- 評分準則主版本不同的結果分開聚合。

## 7. 報導寫作特徵評分準則 v1

### 7.1 維度與聚合方式

| 代號 | 名稱 | 量測 | 聚合（每篇） |
|---|---|---|---|
| N1 | 情緒性用語 | 帶評價色彩、可被中性詞替代的片段 | 每千字標記數，信用加權中位數 |
| N2 | 消息來源與引述歸屬 | 事實性陳述分為具名來源／匿名來源／無來源 | 無來源比例 = 無來源 ÷ 事實性陳述總數；另列匿名比例；加權中位數 |
| N3 | 標題與內文一致 | 一致 < 誇大 < 不支持（序位） | 序位加權中位數；只計入機構 |
| N4 | 評論包裝成報導 | 未標示為評論的作者評價或推測句 | 每千字標記數，加權中位數 |
| N5 | 其他媒體有提及、本文未提及 | 符合 §7.2 的比較事實 | 項數，加權中位數；多數投「不適用」則為不適用；只計入機構 |

- 「字」= 比對鍵前的正規化正文 code point 數；正文少於 300 字的文章不計每千字比率。
- N1–N5 不使用「有爭議」狀態；若各帳號值的四分位距超過準則表中的門檻，維持「初步」並追加 2 位複核者。
- 片段標記單則 ≤ 60 code point；需 ≥2 位指派複核者標到重疊片段（Jaccard ≥ 0.5）才顯示，並標示「n/m 位標記」。
- **文類**（封閉欄位，須共識）：即時新聞／一般報導／特稿專題／專訪／評論社論。評論社論不計 N1、N4；統計依文類分開呈現。
- **爭議用語**：rubric/v1.md 公布封閉清單（如兩岸稱謂），清單內詞彙 v1 不標記，修訂經 PR；清單外照常依 N1 判定。
- 所有參數（門檻、上限、Beta 先驗、權重上限）集中於 `/schemas/parameters.json`，標示可調，並有測試向量。

### 7.2 N5 的前提

- 比較報導須在本文發布時間 ±6 小時內刊出，比較事實須在本文發布時已存在。
- 3 家比較媒體須來自評分方法頁公布的媒體分組清單中的不同組別。
- 不足時填「不適用」。

### 7.3 Skill 的穩定性要求

- N1、N4 先列出所有候選片段再逐一判定，降低順序敏感。
- 評分準則範例涵蓋社會、財經、科技、國際、政治等類別。

### 7.4 作者頁

1. 只顯示逐篇清單與各維度計數，每筆連結到依據；不顯示總評、不排行、不推論動機。
2. v1 **不顯示作者層級中位數**：樣本由使用者選擇，可能被集中挑選弱稿。頁首標示「樣本由使用者選擇，不代表全部作品」。伺服器隨機抽樣機制留待 v2。
3. 作者以「機構＋已確認署名」為識別鍵；需 ≥10 篇「AI 一致」文章才公開，否則顯示「樣本不足」。
4. 首次達到公開門檻前，透過公開聯絡方式通知作者，給予 7 日回應期（§9.7）。
5. 通訊社稿件計入通訊社；「綜合報導」與無具名稿件只計入機構；N3、N5 只計入機構。
6. 只有 `claim_type = 作者陳述` 的事實查核結論計入作者與機構（§8-1）。
7. 機構頁需 ≥5 篇「AI 一致」文章才顯示統計。
8. 頁面註明「本指標為依公開準則之 AI 詮釋，屬對可受公評事項之評論，非對個人之評價」。

## 8. 事實查核方法

既有查核機構的結論是二級證據之一，不具最終決定權。

1. **拆解與歸屬**：主張拆成最小可檢驗單位，並標示封閉欄位 `claim_type`：作者陳述／引述他人（附被引述者）／標題。引述他人的錯誤記在被引述者名下；記者未查證也未反駁的部分在 N2 另計。
2. **證據分級**：一級＝一手資料（統計、判決、原始文件、同儕審查論文、原話紀錄）；二級＝可信二手報導、既有查核報告；三級＝評論、社群貼文。每份證據另記：
   - `proves`：證明「有此陳述」或證明「內容為真」；
   - `stakeholder`：是否為爭議當事方（含政府）；當事方陳述不能單獨作為判定「有誤」的證據。
3. **獨立性**：轉述同一源頭只算一個來源，須追溯並記錄最早出處。
4. **三角驗證**：須主動搜尋反方證據並記錄搜尋關鍵字。
5. **結論**：證實／大致正確／缺少脈絡而誤導／有誤／無法證實／尚待時間驗證；信心高／中／低附理由。
   - 「有誤」與「缺少脈絡而誤導」：須 ≥1 份非當事方一級證據直接牴觸，或 ≥2 份獨立非當事方二級證據；「缺少脈絡」須明確寫出缺少的脈絡與對應證據。
6. **判定時點**：以文章發布時可取得的證據為準，每份證據記錄發布日期；發布後才出現的反證標示「後續資訊已更新」，不計入作者與機構統計。
7. **可推翻**：寫明「出現什麼證據會改變此結論」。
8. **可重現**：記錄搜尋關鍵字、證據網址、取得時間；有存檔連結一併附上。

## 9. 身分、共識、信用與把關

### 9.1 身分與授權

- Worker 是自己的 OAuth 2.1 授權伺服器：S256 PKCE、受保護資源 metadata（`resource` 與連接器網址一致）、401 附 `WWW-Authenticate resource_metadata`、依現行 MCP 授權規格支援 CIMD 或 DCR、redirect_uri 白名單精確比對、同意頁顯示實際 redirect 網域。
- GaoHe 簽發短效、綁定 audience 的 token；refresh token 輪換且可撤銷。token 儲存於 Cloudflare D1 或 KV，依 P0 寫入量決定。
- GitHub 只作上游登入：不要求額外 scope、不保存 GitHub token；以 **GitHub 數字 user id** 綁定帳號；於 callback 讀取 `created_at` 執行 30 天規則。
- 未滿 30 天的帳號：可使用 Skill 與讀取工具，提交不寫入 Cloudflare D1。
- 每帳號每日最多 30 次寫入類呼叫。

### 9.2 任務分派

- 指派由伺服器秘密種子決定；每帳號同時只持有 1 個有時限（24 小時）的指派。
- 略過後冷卻 10 分鐘，每日最多略過 5 次，已略過的項目不再派給同一帳號。
- 共識只採計指派複核者；發起者的提交不計入共識票，只用於觸發指派與作為初步報告。
- 已知答案題（§9.5）混在指派中，比例 5–10%。

### 9.3 共識規則

- **最低票數**：≥3 位合格指派複核者（不含發起者）。
- **事實查核**：以結論完全相同計票（不合併類別）、以帳號數計（不以信用加權），嚴格多數（> 1/2）即採用；**負面結論（有誤、缺少脈絡而誤導）須 ≥ 2/3 一致且符合 §8-5 證據門檻**。未達則「有爭議」，追加 2 位複核者並以全部票數重算；仍未達則維持「有爭議」，不取最負面結論。顯示一致程度 = 多數票數 ÷ 合格票數。
- **N1–N5**：依 §7.1 的聚合方式，以信用加權。
- **群集上限**：同一群集（§9.4）的帳號合計參與某機構「AI 一致」文章的比例不得超過 20%；超過時，依時間由新到舊排除該群集在超額文章中的票並重算。機構未滿 5 篇「AI 一致」文章不公開統計。

### 9.4 信用與群集偵測

- 新帳號前 10 次指派為影子期：不計入共識，也不算 attestation。
- 信用主要依**已知答案題答對率**（Beta 平滑，先驗見 parameters.json）；與共識一致率的權重設上限，避免懲罰正確的少數。信用每日提升有上限，單帳號權重有上限。
- 群集訊號：GitHub 帳號特徵（建立時間、公開 repo 與追蹤數）、OAuth 授權時的瀏覽器 IP（HMAC 以 Workers secret 為金鑰、IPv4 /24、IPv6 /48、保存 90 日）、註冊時間接近、作答相似度、在已知答案題上犯相同錯誤、略過率、任務集中於特定機構。**MCP 請求的 IP 不作為訊號**（預期為 Anthropic 出口）。
- 被偵測的群集共用一個 §9.3 群集額度，並進入人工檢查佇列。

### 9.5 已知答案題庫

- 至少 3 位立場與媒體背景多元的標註者獨立標註；只有標註者一致的項目成為 gold item；公布標註者間一致度與匿名化的標註者背景。
- 依新聞類別與媒體分層抽樣，起始約 50 篇，定期輪換與擴充，並包含內嵌 prompt injection 的文章。
- **gold items 與其 ID 不進入公開 repo 與匯出。**
- 評分準則上線與每次改版前，公布 AI 與人工標註的一致度（Krippendorff's α，依維度與文類分列）；未達準則表門檻的維度只能顯示「初步」。

### 9.6 人工把關（不涉及評分）

以下項目在達到 §9.3 共識後，先進入人工審閱佇列，由具名的維護者群組審閱並留存紀錄，通過才公開：

1. 具名公開的「有誤」「缺少脈絡而誤導」結論；
2. 首次讓作者頁達到公開門檻的結果。

審閱者只確認證據門檻與流程是否符合 §8、§9.3，**不改寫 AI 結論**；不符則退回為「有爭議」。審閱者不得是該項目的提交者或複核者。

### 9.7 申訴、回應與維護者角色

- 維護者群組以公開 GitHub issue／PR 運作，職責：審閱 §9.6 佇列、裁決申訴、發布作者或機構回應、標記更正、處理群集佇列、核准 gold items。所有動作寫入公開 `moderation_log`。
- 作者或機構回應須經網域信箱、官方帳號或人工審核驗證後才公開；申訴需登入並限速。
- 收到申訴後該項目立即「申訴處理中」並暫時排除於統計外；14 日內裁決；裁決者不得是原提交或複核帳號。
- 申訴成立的更正與撤回同步進入開放資料匯出。

### 9.8 Prompt injection

- Skill 只評可見正文，並把文章、證據與他人文字一律視為資料。
- 他人自由文字只出現在 `untrusted_text` 欄位；複核任務不含發起者自由文字。
- 同一篇文章的提交若一致地偏離準則預期，送人工檢查。
- 伺服器只接受封閉標籤與固定格式；理由欄位不影響計算。

## 10. 介面與開發者體驗

### 10.1 Claude 內的流程

進度逐步簡短回報 → 報告 → 詢問是否提交 → 詢問是否協助一個複核任務。上線引導說明：需啟用程式碼執行；可設定對 GaoHe 唯讀工具（`readOnlyHint`）一律允許。

### 10.2 查核報告（artifact）

依序：標題／機構／作者／時間／段落確認狀態 → 主張結論統計 → N1–N5 卡片（初步或 AI 一致 n/required）→ 原文（對話中的 artifact 可顯示使用者自己抓到的原文，淡色標示）→ 主張卡（結論、信心、證據等級與證明對象、反方證據、可推翻條件）→ 側欄機構與作者紀錄（由 Skill 預先取得並嵌入的靜態資料）→ 頁尾準則版本、模型、搜尋紀錄。

### 10.3 深入研究

每張主張卡提供 5 個建議追問（在對話中提出；artifact 內提供複製按鈕）：追溯原始出處、找反方證據、看其他媒體怎麼報導、整理事件時間軸、補充背景知識。結果可以 `kind = supplement` 提交，同樣經複核。

### 10.4 公開網站

繁中、手機與深色模式、WCAG 2.1 AA。頁面：首頁搜尋、媒體頁、作者頁（§7.4）、文章頁（不顯示原文）、評分方法頁、申訴頁、開放資料下載頁、維護紀錄頁。所有使用者產生內容一律跳脫輸出；外部連結加 `rel="noopener nofollow ugc"`。

### 10.5 Repo 結構

```text
/schemas   JSON Schema、parameters.json、正規化與切段測試向量
/skill     SKILL.md、rubric/v1.md（含爭議用語清單）、報告範本、打包腳本
/server    Cloudflare Workers（TypeScript）
/web       Astro 網站
/legacy    凍結的 Python 本機版
```

- `npm run dev` 同時啟動 wrangler 本機伺服器（含 Cloudflare D1 模擬）與網站。
- 公開 REST API 附 OpenAPI 文件。
- 評分準則改版經 PR，附變更紀錄、版本號與 §9.5 一致度結果。

### 10.6 開放資料匯出

- 匯出：機構、文章（URL、段落 ID、狀態、版本）、AI 一致與有爭議的結論與統計、通過 §5.1 上限的短引文、更正紀錄、moderation_log。
- 不匯出：段落全文、accounts、GitHub 對應、IP 訊號、gold items、初步項目的個別結果。提交者以每次匯出輪換的假名表示。
- 作者層級資料以假名 ID 匯出，作者姓名對應表只在網站上顯示，不進入匯出。

## 11. 個人資料

- 責任主體與聯絡窗口：專案維護者（上線前公布）。

## 12. 錯誤處理與測試

### 12.1 錯誤處理

| 情況 | 處理 |
|---|---|
| 抓不到原文或只有樣板內容 | `report_unavailable`，不評分，不繞過 |
| 段落不一致 | 只用已確認段落；不穩定則停在初步 |
| 文章改寫 | 依 §6.1-7 建立新版本 |
| 格式錯誤、引文找不到或不唯一 | 回傳錯誤碼；Skill 最多重送 2 次 |
| 找不到證據 | 「無法證實」 |
| 複核衝突 | 「有爭議」，追加 2 位 |
| 免費額度接近上限 | 寫入預算達 90% 時拒絕新提交（保留部分額度給複核）；網站與 API 讀靜態 JSON 不受影響 |
| 連接器未安裝或連不上 | Skill 仍完整查核並產出報告，註明無法提交與無累計紀錄 |
| 內嵌指令 | §9.8 |

### 12.2 測試（CI 不呼叫任何 AI）

1. 格式測試：`/schemas` 正例與反例（含非 http/https URL、超長引文、超量標記）。
2. 正規化與切段：比對鍵、Cf 字元、引號變體、code point 位置（含罕用字與 emoji），Skill 腳本與伺服器共用測試向量。
3. 驗證器：引文定位、`QUOTE_NOT_FOUND`／`QUOTE_AMBIGUOUS`、封閉標籤、數量上限、5.1 引文總量上限。
4. 聚合器性質測試：發起者不計票；未滿 3 位合格指派複核者不會「AI 一致」；負面結論需 2/3；群集上限 20%；影子帳號不影響結果與 attestation；主版本不混算；盲審期間任何讀取端不洩漏個別結果。
5. 攻擊情境：2–5 個串通帳號灌票、兩個帳號 attestation 偽造段落、偽造 metadata、反覆略過挑任務、自我複核、刷提交、所有 MCP 請求帶 Anthropic 出口 IP、零寬字元干擾雜湊、主張與理由內嵌注入、XSS。
6. 整合測試：wrangler 本機模擬跑完整「OAuth discovery → authorize → token → refresh → 快照 → 提交 → 指派 → 複核 → 聚合 → 人工把關 → 公開 API → 匯出」；驗證匯出不含全文與帳號資料。
7. Skill 品質評估（手動，不進 CI）：以 gold items 實際執行 Claude，量測一致度與穩定性；準則改版前後都要跑。
8. 網站：Playwright 無障礙檢查與手機截圖。
